# AI 숏츠 제작·승인·렌더 운영 가이드

기준: 2026-09-05, 구현 PR #63 병합 이후. 이 문서는 대화에서 합의한 제작 원칙과 실제 워크플로 동작을 연결한다. 미구현 항목은 마지막 절에 따로 표시한다.

## 1. 제작 목표와 역할

목표는 블로그를 페이지별로 요약한 슬라이드가 아니라, 글의 한 가지 생각을 관계와 움직임으로 설명하는 모션 인포그래픽이다. AI는 후보 각도·스크립트·의미 단위 자막·장면 구성·도식 명세를 작성하고, 렌더러는 허용된 명세를 재현한다. 사람은 사실·강조점·출처·시각적 의미를 승인한다. 자동 생성 또는 CI 성공은 콘텐츠 승인이나 게시 승인이 아니다.

공통 아트디렉션은 검정/차콜 바탕, 흰색 주요 텍스트, 회색 보조선, 모노크롬 사진과 절제된 모션이다. 불필요한 `PHOTO / PHOTO`, `VISUAL / ROI-CURVE` 같은 템플릿 라벨은 넣지 않는다. 상세 원칙은 [creative-system.md](creative-system.md)를 따른다.

## 2. 실제 제작 순서

1. **후보 생성:** Actions의 **Generate blog shorts**에 블로그 URL을 입력한다. 생성 결과는 `shorts/content/<post-slug>/candidate-XX.json` 파일을 담은 PR로 받는다. 원문의 독립적인 논점과 훅을 선택하고, 원문에 없는 경험·통계·결과를 만들지 않는다.
2. **대본·장면 검토:** PR 본문의 체크박스는 사용할 후보의 기록용이다. PR 생성·수정에서는 타입 검사와 단위 테스트만 실행하며 체크 변경·머지로는 프리뷰를 생성하지 않는다. 무음 프리뷰가 필요하면 **Shorts pipeline check**를 수동 실행하며 `generate_previews`(기본 해제)를 체크하고 `manifest`를 입력한다.
3. **스토리보드 생성:** **Build blog shorts storyboard**를 수동 실행하고 `generate_previews`를 체크한다. `manifest`에는 `shorts/content/<post-slug>/candidate-01.json`처럼 저장소 루트 기준 경로를 입력하고, 후보가 있는 브랜치를 선택한다. 체크 해제 시 렌더 작업 전체를 건너뛴다. 이 단계는 TTS를 호출하지 않고 추정 장면 길이로 대표 스냅샷을 만든다.
4. **휴대폰 검토:** 실행 요약에 있는 Draft Release 링크를 연다. 2열 모아보기 JPG로 장면 순서를 보고, PDF 또는 개별 PNG로 글자와 도식을 확인한다. Draft를 볼 수 있는 저장소 권한이 필요하다. 수정이 필요하면 JSON을 변경하고 스토리보드를 다시 만든다.
5. **최종 렌더 승인:** 검토한 manifest로 **Render blog shorts**를 수동 실행하고 `storyboard_approved`를 체크한다. 체크하지 않으면 작업이 중단된다. 실제 TTS와 최종 영상 제작은 이 단계에서 수행한다.
6. **최종 검수·게시:** 결과 아티팩트에서 MP4, SRT, 미디어 출처, 릴스용 텍스트와 스크립트를 확인한다. 실제 음성·자막 타이밍·움직임을 재검토한 뒤 게시한다. 현재 SNS 자동 업로드 단계는 없다.

### 승인 시 유의사항

현재 승인은 수동 체크박스이며, 승인된 스토리보드와 manifest 해시/커밋을 자동 대조하는 강제 게이트가 아니다. Release에 기록된 source commit과 렌더할 버전을 사람이 확인해야 한다. 승인 후 JSON 또는 렌더 코드가 달라졌다면 스토리보드를 다시 검토한다. 로컬 렌더 명령은 Actions 승인 체크를 거치지 않으므로 같은 운영 규칙을 수동으로 지킨다.

한 장면당 PNG 한 장은 레이아웃 검사용이지 전체 모션 검증이 아니다. 스토리보드는 추정 길이, 최종 영상은 실제 음성 길이를 사용하므로 자막과 전환 타이밍은 최종 MP4에서 다시 확인한다.

## 4. 표현력을 자동화하는 규칙

장면마다 먼저 설명할 관계를 선택하고, 그 다음 시각화와 모션을 정한다. 키워드에 아이콘 하나를 붙이는 방식에 머물지 않는다.

| 설명하려는 관계 | 우선 검토할 표현 |
| --- | --- |
| ROI·효율·격차·누적 | 곡선, 기울기, 입력/출력 비교와 필요한 지점 확대 |
| 레버리지·균형·트레이드오프 | 레버/시소의 회전과 무게 이동 |
| 병목·대기 | 관문 앞에 입력이 쌓이는 흐름 |
| 구조·연결·정신 모형 | 공간 도식, 노드 관계, 전체에서 부분으로 시점 이동 |
| 경험·현장·맥락 | 의미 있는 사진을 공통 모노크롬 스타일로 정규화 |

이는 연출 선택 기준이며, 모든 표현을 구현한 자동 템플릿 목록은 아니다. 장면 전환, 요소별 등장/강조, 카메라 이동은 별개로 설계한다. 장면당 1–3개의 의미 있는 사건을 우선하고, 모든 요소가 계속 움직이지 않도록 한다. 그래프의 실제 데이터와 물리적 비유를 구분하며 가짜 수치를 만들지 않는다.

자막은 `그럴 / 수 / 있다`처럼 잘게 쪼개지 않고 의미 단위로 묶는다. 공백 제외 4자 이상을 기본 지향점으로 두되 의도적인 짧은 강조어는 허용한다. 문장당 핵심 강조는 보통 1–2곳으로 제한하고 스크립트·자막·시각적 사건이 같은 핵심을 가리키도록 한다.

사진 자동 검색은 현재 Openverse의 CC0/Public Domain Mark 필터를 사용한다. Pexels, Mixkit, SVG Repo, LottieFiles 등은 조사된 후보 풀이지 모두 자동 연동된 공급원이 아니다. 자동 검색 메타데이터만 믿지 않고 원출처의 사용 조건을 게시 전에 확인한다.

## 5. 엔진 선택과 물리 시뮬레이션

영상 전체의 합성과 인코딩은 Remotion이 담당한다. `diagramSpec`의 renderer 선택은 장면 내부 도식의 백엔드 선택이다. Canvas 경로는 별도 임의 Canvas2D 구현이 아니라 Motion Canvas를 사용한다.

| 설정/상태 | 동작 |
| --- | --- |
| `renderer: auto`, physics 없음 | Remotion의 React SVG 도식 |
| `renderer: auto`, physics 있음 | Motion Canvas 도식 |
| `remotion` 또는 `motion-canvas` 명시 | 지정 엔진 우선 |
| 엔진 컴포넌트/비동기 어댑터 실패 | 같은 계산 상태로 다른 엔진을 한 번 시도 |
| 잘못된 명세 또는 대체 엔진도 실패 | 렌더 중단. 의미 없는 아이콘으로 대체하지 않음 |
| `diagramSpec` 없는 기존 후보 | 기존 PresetVisual 경로 |

물리는 Matter.js가 담당한다. 중력, 충돌, 질량, 마찰, 반발, 초기 속도, 정적 바닥과 고정 회전축을 지원한다. 각 프레임은 초기 세계에서 1/60초 고정 간격으로 다시 계산하므로 역방향 탐색과 병렬 렌더 순서에 의존하지 않는다. `physics.seconds`의 계산 시간을 장면 진행률에 대응시켜 스토리보드와 최종 렌더에서 같은 진행률의 물리 상태를 유지한다.

물리 물체는 사각형 또는 정원이며 물리가 위치·회전을 소유한다. 해당 물체의 이벤트에는 opacity만 허용한다. 회전축과 정적 바닥을 명세에 작성하며, 화면 밖 이동이나 보기 나쁜 충돌까지 자동 교정해 주지는 않는다. 800×560 도식 영역의 노드·이벤트 수와 물리 시간을 제한한다. 자유 생성 코드를 실행하는 방식이 아니다.

상세 스키마와 제약은 [diagram-engine.md](diagram-engine.md), 시소 예시는 [physics-example.ts](../src/visuals/physics-example.ts)를 참고한다. 폴백은 브라우저 프로세스 종료나 CLI 전체의 실패까지 복구하지 않는다.

## 기존 스토리보드 리뷰

Review and improve shorts storyboard 작업은 `manifest`만 지정해도 된다. `storyboard_source`를 비우면 현재 후보 JSON과 일치하는 발행본을 찾아 최근 업데이트 순으로 선택한다(Draft 포함). 같은 시각이면 Release ID가 큰 것을 우선한다. 특정 버전을 지정하려면 `storyboard_source`에 Draft Release 주소 또는 태그를 넣는다. 예: `shorts-storyboard-33984227357`. 초안 URL의 `untagged-…` 별칭도 지원한다. 앞으로 생성하는 스토리보드 본문에는 복사할 태그를 표시한다.

리뷰는 Release 본문에 기록된 고정 커밋 링크에서 원본 JSON과 스토리보드 Markdown·장면 PNG를 읽는다. 현재 브랜치나 최신 에셋으로 대체하지 않는다. 과거 Release에서 Markdown 링크가 고정되지 않았더라도 본문에 필요한 모든 PNG의 고정 링크가 있으면 사용할 수 있다. 도식·영상 배경은 발행 당시의 initial/change/result 이미지를 모두 가져온다.

현재 후보 JSON이 당시 JSON과 다르면 중단해 새로운 편집을 덮어쓰지 않는다. 자동 탐색은 다른 후보와 JSON이 다른 발행본을 건너뛴다. 일치하는 발행본이 없으면 중단하며 임의의 과거 JSON을 덮어쓰거나 새로 렌더하지 않는다. 선택된 발행본의 이미지가 불완전하면 더 오래된 발행본으로 조용히 바꾸지 않는다. 이미지 누락·다운로드 실패·서로 다른 커밋의 이미지가 섞인 경우에도 중단하며 원본 재렌더로 우회하지 않는다. 렌더러만 변경되고 JSON이 같으면 그대로 과거 이미지를 리뷰할 수 있다.

가져온 원본은 리뷰 아티팩트의 `before.json`, 이미지는 `before/`, 출처 커밋·Release·각 파일 SHA-256은 `review-source.json`에 기록한다. AI 호출 전에 다시 무결성을 확인한다. AI 수정 후에만 새 스토리보드를 렌더해 `after/`에 저장한다. 이 작업은 기존 Release를 수정하지 않는다.

## 6. 검증과 운영 체크리스트

- 후보: 원문 근거, 독립적인 논점, 자연스러운 말투, 중요한 단어의 강조, 출처와 라이선스.
- 스토리보드: 장면 순서, 글자 크기/잘림, 반복 레이아웃, 불필요한 라벨, 사진·도식의 통일감.
- 모션: 관계가 실제 움직임으로 전달되는지, 물체가 화면을 벗어나지 않는지, 시선 이동이 자막과 충돌하지 않는지.
- 최종 영상: TTS 발음과 속도, 자막 의미 단위, 음성과 강조 타이밍, 전환, 엔딩과 게시 문구.
- 개발 변경: `cd shorts` 후 `npm test`, `npm run typecheck`, PR 렌더 CI를 확인한다. 엔진 자체의 strict 테스트와 강제 실패 폴백 테스트를 구분한다.

엔진 구현 시 단위 테스트 7개, 타입 검사, 두 백엔드 및 폴백 정지 프레임, 120프레임 물리 MP4가 [검증 실행](https://github.com/dohyeon-kr/dohyeon.kr/actions/runs/33952745599)에서 통과했다. 이는 특정 구현 커밋의 회귀 검증 기록이며 이후 생성되는 후보의 연출 품질을 보증하지 않는다. 당시 Motion Canvas의 `ReadOnlyTimeEvents` 최상위 export 참조 오류는 실제 하위 모듈 import로 수정했다.

## 영상 배경 운영

페이지에 B-roll을 깔고 제목·도식·자막을 합성하는 연출은 [영상 배경 제작 가이드](video-background-guide.md)를 따른다. backgroundVideo 스키마·등록 소스 다운로드/검증·풀블리드 재생을 지원한다. 새 소스는 register-video.mjs로 등록하며 사용 구간은 실제 파일 길이 안에서 고른다. 최종 장면 길이가 영상보다 길면 명시적 loop가 없을 때 중단한다. 대표 스틸 외에 최대 밝기/이동, 루프·전환 경계와 실제 TTS 길이의 재생·오디오를 검수한다.

## 7. 미구현·추후 검토 항목

- 템플릿 공개 Release에 **각 장 PNG + 전체 모아보기 + PDF**를 추가하는 것: 필요성은 논의했으나 아직 적용하지 않았다.
- 승인 기록을 manifest 해시/커밋과 강제로 연결하는 것: 현재는 수동 확인이다.
- 최종 후보 MP4도 Release로 전달하는 것: 현재는 아티팩트다.
- 후보별 시작/중간/끝 프레임 또는 모션 미리보기로 승인하는 것: 현재 스토리보드는 장면당 대표 PNG 한 장이다.
- 임의 경로, 자동 그래프 레이아웃, 시각적 품질 자동 평가·재생성, 추가 애셋 공급원: 현재 구현 범위와 구분해 별도 설계한다.

이 문서는 운영 흐름을 기록한 것이며, 위 미구현 항목의 실행·게시를 자동 승인하지 않는다.


## 리뷰 사진 검색 복구

AI 리뷰에서 기존 사진 검색어가 같으면 확보한 사진을 유지한다. 새 검색어로 사진을 찾지 못하면 같은 리뷰 모델이 장면의 피사체·행동을 유지하는 짧은 검색어를 최대 3개 제안하고 순서대로 다시 검색한다. 사진 URL은 모델이 작성하지 않으며 실제 검색 결과나 기존 검토된 사진 목록의 출처를 유지한다. 검색어 변경과 이유는 후보의 연출 설명에 기록한다.

사진 계획 호출은 장면당 1회·실행당 최대 21회이고 도식 수정과 같은 40분 마감 시각을 사용한다. 사진을 끝내 확보하지 못하거나 API가 실패하면 원래 장면과 대본을 유지한 채 중단하며, visual-repair.json에 장면 번호·검색어·시도 결과를 저장한다. 사진 실패를 텍스트 장면으로 변환해 리뷰를 통과시키지 않는다. 이 복구는 검색 결과 확보를 돕는 단계이며 실제 이미지 적합성·다운로드·크롭·렌더 검수를 대신하지 않는다.
