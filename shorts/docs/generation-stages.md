# 생성 액션 내부의 3단계 JSON 처리

`generate-shorts.yml`의 `generate-candidates.mjs` 호출 내부에서 실행한다.
추가 미리보기·이미지 렌더·TTS·워크플로 호출 없이 모델이 JSON을 순차 전달한다.
기존 읽기용 Markdown 생성·후보 선택·PR 처리에는 최종 후보만 전달한다.

| 단계 | 모델 / reasoning.effort | 책임과 출력 |
| --- | --- | --- |
| 분석·대본 | gpt-6-astra / low | 원문 주장·논거·사례·조건, 정확한 인용과 근거 ID, 후보별 질문·답·선택 범위·제외 논점·용어 정의, 기승전결 대본과 구간별 전제·연결 이유 |
| 장면 생성 | gpt-5.6-sol / low | 분석 JSON을 받아 원문자 대본을 보존하며 장면·자막 분할, 사진·도식·모션 구성 |
| 리뷰·수정 | gpt-6-astra / low | 원문 + 분석 + 장면 JSON을 검토하고 필요한 수정만 직접 수행. 문제 위치·이유·수정 내용·해결 여부와 최종 후보 반환 |

모델은 `generation-stages.mjs`의 STAGE_MODELS로 고정한다. 공유 `SHORTS_TEXT_MODEL`이 세 단계를 같은 모델로 덮어쓰지 않는다. 해당 변수는 기존 도식 오류 복구에 계속 적용된다. 정상 편집 경로는 총 3회 호출이며 SDK의 전송 재시도와 기존 도식 복구 호출은 별도다. 새 편집 왕복 루프는 추가하지 않는다.

## 매체별 역할과 지침 배분

블로그는 저자의 경험과 판단 과정, 근거·반론·적용 조건을 충분히 보여준다. 숏츠는 그 안의 한 질문과 답을 독립적으로 완결하고 관점을 기억하게 한다. 블로그는 숏츠에서 생략한 확장 맥락을 제공하며 숏츠의 답을 CTA 뒤로 미루지 않는다.

공통 기준은 원문 충실성·필요한 전제 보존·출력 계약이다. 분석에는 화면 제약을 주지 않는다. 생성에는 렌더러 문법과 화면 규칙, 리뷰에는 논리 검토를 우선한 평가 기준을 제공한다. 분석 결과는 요약 메모가 아니라 뒤 단계가 보존할 대본과 근거의 기준이다.

- 발췌는 다룰 범위 선정이다. 원문 문장을 단순히 이어 붙이지 않고 자연스러운 발화 대본을 쓴다.
- 기승전결은 질문 → 근거·사례 → 핵심 이유/관점 발전 → 답이다. 균등 분량과 억지 반전을 요구하지 않는다.
- 연결에 필요한 설명을 남기고 별도 논점을 덜어낸다. 독립 질문과 결론이 필요한 세 소주제는 별도 후보로 분리한다.
- 6~9장과 18~21장은 기본/확장 참고 범위다. 장수와 세 부분을 채우기 위해 늘리지 않는다. 동일 질문의 심화일 때만 확장한다.
- 장면 생성은 대본의 비공백 문자를 그대로 보존한다. 장면 분할·공백·줄바꿈은 허용하지만 논거·조건 삭제나 재작성은 코드에서 거부한다.
- 리뷰만 논리 수정을 할 수 있다. 원문과 선택 범위·중심 답을 보존하고 관련 자막·화면도 함께 고친다. 해결할 수 없으면 이유를 남기고 실패한다.

## 화면 기본값

- 자막이 주된 언어 전달 수단이다. 중앙 타이포는 기본 제외(`headline: ""`, `subline: null`). 특별한 질문·결론 강조만 이유를 기록해 허용한다.
- 중앙에는 의미 있는 사진·영상·도식을 선택한다. 채울 내용이 없으면 비워도 된다. 자막과 중앙 문구의 중복을 줄인다.
- 도식은 식별에 필요한 이름·수치·구분·축 라벨만 사용한다. 관계는 위치·크기·연결·움직임으로 전달한다. 제거한 설명 중 논증에 필요한 내용은 내레이션에 남긴다.
- 순간의 중심 요소는 하나다. 프레젠터는 질문·정리 장면에서 선택하고 사진·도식 위에 상시 생성하지 않는다. 기존 수동 후보의 명시적 오버레이는 이 작업에서 수정하지 않는다.
- 자막은 큰 고정 크기와 의미 단위 최대 두 줄을 목표로 한다. 반복 크기 변화 대신 제한적 강조를 쓴다. 현재 생성 스키마에는 자막 크기·숨김 제어가 없으므로 임의 필드를 만들지 않는다. 이 변경은 렌더러의 자막 크기를 바꾸지 않는다. 실제 크기·타이포 통합·노출 시간은 후속 렌더 검수에서 확인한다.

## 리뷰와 하드 검증

대본만 이어 읽어 도입/결론 일치, 전제·근거, 용어·주어 일관성, 별도 논점, 원문 조건을 확인한 뒤 화면 정보량을 검토한다. findings에는 후보 ID와 위치, narrative/visual/fidelity 유형, 문제·이유·수정·해결 여부를 남긴다. 취향에 따른 전면 재작성은 금지한다.

코드가 후보 개수/ID/순서, 근거 인용의 원문 포함 여부(공백 정규화), 근거 참조 ID, 기승전결 순서, 2단계 대본 보존, 자막/내레이션 일치, 리뷰 수정 이유와 미해결 문제를 확인한다. 정확한 인용 검사는 논거가 주장을 뒷받침한다는 의미 검증을 대체하지 않는다. 리뷰 후 후보 스키마와 기존 도식·모션 검증도 적용한다.

`scope=json-only`: 실제 가독성·겹침·TTS 길이·자막 노출·움직임 경쟁·이미지 확보를 확인 완료로 판정하지 않는다. 실제 매체 확보는 리뷰 후 기존 enrichVisuals에서 처리한다.

진단 경로에 source.json, analysis.json, visual.json, review.json 및 실패 시 오류 JSON을 저장한다. 기존 아티팩트 보존(14일)을 사용하며 shorts/content에 중간 결과를 발행하지 않는다. raw-plan.json은 이제 리뷰 후 최종 후보이고, 리뷰 이전 장면은 visual.json에 남는다. 자동 이어받기를 지원한다는 의미는 아니다.
