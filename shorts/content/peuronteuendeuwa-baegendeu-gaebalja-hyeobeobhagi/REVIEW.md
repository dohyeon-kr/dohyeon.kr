## 최종 사용자 요청

2장의 문서 확인·미안함 문단 전체를 아래 소개로 대체했다. 이전의 부분 교체 지시는 이 최종 지시로 대체된다.

> 이번에는 옆자리 백엔드 개발자와 같이 일하면서 워크플로우를 정한 몇 가지 사례에 대해 이야기하고자 합니다.

개선 성과를 강조하는 도입 대신 함께 정한 사례를 소개한다. 뒤의 중복 소개는 제거했다.

세 축은 SDK / Bruno / 요청 추적이다. 티켓·PR은 갑자기 등장하는 별도 기억력 문제가 아니라 세 과정에서 나온 결정을 남기는 공통 작업이다. 장수 할당을 채우지 않고 사례별 배경·변화·조건을 보존했다.

## 원문 충실성

- SDK: 원문의 자동 동기화와 프론트엔드 버전 선택의 필요, 패키지 배포를 보존했다. SDK 버전 고정으로 서버 호환성까지 해결됐다고 말하지 않는다. 변경을 알아보기 쉬워졌다는 관찰까지만 말한다.
- Bruno: 인증 요청으로 토큰을 받아 저장·재사용한 경험, 동료 반응, 요청 공유를 보존했다. 무료 횟수 제한·Electron 제작은 이 후보에서 제외했다.
- 추적: 프론트엔드 기록과 백엔드 추적을 traceparent로 연결한 경험, 문의 시 같은 요청을 따라가는 효과를 보존했다. 가짜 시간·효율 수치를 넣지 않았다.
- 티켓·PR: 요청 이유·진행 상태와 대화 뒤 결정 기록을 보존했다.
- 변경 확인→요청 실행→추적은 이번 대본의 설명 순서다. 모든 요청마다 이 도구들을 반드시 연속 실행한다는 새로운 운영 규칙을 주장하지 않는다.

## 검증

`CandidateSchema`, 모든 내레이션/자막 beats 일치, 장면 모션 계약, 제목·비교 문구 최소 크기와 자막 최대 두 줄의 보수적 `fitCopy` 검사 통과. traceparent 도식은 `validateDiagram`과 `validateDiagramLayout` 검사 통과. 연결선은 고정 길이·불투명도 등장으로 설정했고, 라벨과 떨어뜨렸다. 이 검사는 실제 렌더와 오디오 검증을 대체하지 않는다.

### 도식 설계에 참고한 공식 문서

조사는 표현의 정확성 보강용이다. 원문에 없는 저자의 경험·성과·새 운영 규칙을 내레이션에 추가하지 않았다.

- [GitHub Packages npm registry](https://docs.github.com/packages/working-with-a-github-packages-registry/working-with-the-npm-registry): 발행과 의존성 설치를 분리한 SDK 도식의 관계를 확인.
- [Bruno 환경변수](https://docs.usebruno.com/variables/environment-variables), [Request chaining](https://docs.usebruno.com/v2/testing/script/request-chaining): 요청에서 받은 값을 후속 요청에 재사용하는 흐름을 확인. 모든 요청마다 자동 로그인한다거나 무한 유효 토큰이라는 의미는 넣지 않음.
- [W3C Trace Context](https://www.w3.org/TR/trace-context/): traceparent의 추적 문맥 전달 역할을 확인. traceparent 전체가 전 구간에서 동일하다고 표시하지 않으며 고정 가짜 ID·처리 시간을 만들지 않음.
