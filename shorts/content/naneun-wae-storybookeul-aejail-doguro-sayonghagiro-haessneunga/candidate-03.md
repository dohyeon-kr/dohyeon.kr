# API를 바꾸기 전 화면부터 확인하기

**템플릿:** Notebook Grid · 가벼운 에세이 (notebook-grid)

원본: [candidate-03.json](candidate-03.json)

JSON에서 자동 생성한 검토용 스토리보드입니다. 수정은 원본 JSON에 반영한 뒤 다시 생성하세요. 연출 설명은 기획 의도이며, 실제 배치·동작은 렌더된 스냅샷과 영상으로 확인합니다. 음성 생성 전이므로 재생 시간은 확정하지 않습니다.

**첫 문장:** API 응답이 비어 있으면 화면은 어떻게 바뀔까요? 이걸 확인할 때마다 목 코드를 고쳐야 했습니다.

**기획 의도:** MSW 응답 오버라이드의 협업 가치와 검증 범위에 집중한 원문 기반 후보. 다른 후보와 독립적인 질문과 답으로 구성했다. 정적 도식 재사용은 동일한 관계를 이어 설명하기 위한 의도적인 선택이다.

**원문:** [나는 왜 Storybook을 애자일 도구로 사용하기로 했는가](<https://blog.dohyeon.kr/naneun-wae-storybookeul-aejail-doguro-sayonghagiro-haessneunga/>)

## 1. 도입 — 빈 응답이면 화면은?

**내레이션**

API 응답이 비어 있으면 화면은 어떻게 바뀔까요? 이걸 확인할 때마다 목 코드를 고쳐야 했습니다.

**화면 구성**

- 주 문구: 빈 응답이면 화면은?
- 배치: 노트 그리드 · 사진은 흰 인화지 여백과 반투명 테이프, 비교는 2단, 도식은 넓은 중앙 영역
- 발표자: 우측 하단 원형 바스트 상시 표시 (본문 전환 유지). 최종 TTS 단어 타임스탬프에 맞춘 입 모양과 발화 구간 노딩. 단어 내부 음절 타이밍은 근사이며 실제 음성 검수 필요. 무음 미리보기에서는 입·노딩 트랙을 만들지 않음.
- 전달할 관계: 원문 문단 p18의 관계를 설명한다.
- 표현 방식: 문장 중심
- 표현 이유: 원문 질문 또는 판단을 짧은 타이포로 강조하고 설명은 자막으로 전달한다.

**연출 흐름**

1. 주 문구 등장
2. 결과 강조

장면 전환: 서서히 전환

**자막과 낭독 리듬**

1. API 응답이 비어 있으면
   - 강조 중 · 자연스럽게 · 뒤에 80ms 쉼
2. 화면은 어떻게 바뀔까요?
   - 강조 중 · 자연스럽게 · 뒤에 80ms 쉼
3. 이걸 확인할 때마다
   - 강조 중 · 자연스럽게 · 뒤에 80ms 쉼

   - 강조 중 · 자연스럽게 · 뒤에 180ms 쉼

## 8. 마무리 — 바꾸기 전에 함께 확인

**내레이션**

API를 바꾸기 전에 화면에 미칠 영향부터 함께 봅니다. MSW 패널은 그 논의를 앞당기는 도구입니다.

**화면 구성**

- 주 문구: 바꾸기 전에 함께 확인
- 배치: 노트 그리드 · 사진은 흰 인화지 여백과 반투명 테이프, 비교는 2단, 도식은 넓은 중앙 영역
- 발표자: 우측 하단 원형 바스트 상시 표시 (본문 전환 유지). 최종 TTS 단어 타임스탬프에 맞춘 입 모양과 발화 구간 노딩. 단어 내부 음절 타이밍은 근사이며 실제 음성 검수 필요. 무음 미리보기에서는 입·노딩 트랙을 만들지 않음.
- 전달할 관계: 원문 문단 p21의 관계를 설명한다.
- 표현 방식: 문장 중심
- 표현 이유: 원문 질문 또는 판단을 짧은 타이포로 강조하고 설명은 자막으로 전달한다.

**연출 흐름**

1. 주 문구 등장
2. 결과 강조

카메라: 고정

장면 전환: 서서히 전환

**자막과 낭독 리듬**

1. API를 바꾸기 전에
   - 강조 중 · 자연스럽게 · 뒤에 80ms 쉼
2. 화면에 미칠 영향부터 함께 봅니다.
   - 강조 중 · 자연스럽게 · 뒤에 80ms 쉼
3. MSW 패널은 그 논의를
   - 강조 중 · 자연스럽게 · 뒤에 80ms 쉼
4. **앞당기는 도구입니다.**
   - 강조 강 · 여운을 두어 · 뒤에 180ms 쉼
