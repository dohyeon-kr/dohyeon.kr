# 통합본 검토 기록

사용자 요청에 따라 시리즈 대신 candidate-01 한 편으로 통합했습니다.
제목은 **완성하고 보여주니까, 완성하고 고치게 됐다**입니다.

- 목적: 완성한 뒤에야 함께 화면을 보던 구조가 수정 시점도 늦췄다는 경험.
- 방법론: 아직 고치기 쉬운 구현 중간에 조작 가능한 화면을 공유.
- 구체적인 방법: 시작 조건 조합, 실제 버튼을 통한 상태 전이, 테스트용 API 응답 변경.
- 범위와 결론: 실제 앱·테스트의 역할을 남기고, 아직 고치기 쉬울 때 함께 눌러본다는 판단으로 회수.

본문 12장면과 공통 CTA 1장면입니다. 개별 사례에 별도 도입·결론·CTA를 붙이지 않았습니다.
서비스 고유 용어를 긴 문구·빈 데이터·버튼 클릭 등 원문 속 보편적인 사례로 바꿨습니다. 스토리북과 API는 첫 등장에 역할을 설명합니다.
22→3은 스토리 개수이며 개발 속도 개선 수치가 아닙니다. MSW가 실제 API를 수정한다고 설명하지 않습니다.

새 도식은 3·9·11장면에서 각각 한 번 사용합니다. 세 입력 도식은 조건·행동·응답을 모두 설명한 뒤 정리하는 역할입니다.
패널의 실제 조작 시연은 없으며, 해당 구간은 타이포와 내레이션으로 설명합니다.
프레젠터 우측 하단과 기존 템플릿 설정은 유지했습니다.

## 분석과 선택

analysis.json은 초기 분석 대안 3개의 형식을 유지합니다. 첫 항목만 현재 통합본으로 갱신했고 나머지 두 항목은 미선택 분석 기록입니다.
실행 가능한 후보 파일과 스토리보드는 candidate-01만 남겼습니다. 최소 3개 대안을 요구하는 자동 생성 스키마를 임의로 바꾸지 않았습니다.

## 검증

원문 연속 인용·근거 ID·서사 순서, 선택 대본과 분석의 일치, CandidateSchema, validateRevision, 자막 일치, 모션·프레젠터·선택 경로, CTA 한 장을 검사합니다.
읽기용 Markdown은 describe-candidates.mjs로 재생성합니다.

## 미검증 및 의존성

실제 렌더 프레임·전환·모바일 가독성·TTS·립싱크는 미검증입니다. 유료 API는 실행하지 않았습니다.
세로 사진·모든 헤딩 스크리블·100px 하향 이동·도식 contain 처리는 PR #147에 의존합니다.
원본 블로그의 도식 3장은 교체·발행 완료했고 공개 페이지의 로딩도 확인했습니다. 이번 쉬운 사례 수정은 숏츠에만 적용합니다.
viralScore 75는 스키마 호환 임시값으로 성과 예측이 아닙니다.
