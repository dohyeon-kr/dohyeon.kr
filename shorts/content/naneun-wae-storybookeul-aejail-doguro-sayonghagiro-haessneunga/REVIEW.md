# 검토 기록

원문 전체와 기존 도식 3장, 실제 UI 캡처 3장을 Ghost 편집 화면에서 확인했습니다.
본문과 UI 캡처는 변경하지 않았습니다. 도식만 새로 제작했고, 교체용 PNG를
각 후보의 `image.originalUrl`에 커밋 SHA로 고정해 삽입했습니다.

| 후보 | 중심 질문 | 결론 | 새 도식 |
| --- | --- | --- | --- |
| 01 | 작업을 잘게 나눠도 왜 피드백은 늦는가? | 아직 고치기 쉬울 때 함께 보고 다음 결정 | feedback-timing |
| 02 | 22개 화면을 3개 시나리오로 바꾼 이유는? | 시작 조건을 조합하고 사용자 행동으로 상태 전이 | three-inputs |
| 03 | API 수정 전에 UI 영향을 확인하려면? | MSW 응답을 바꿔 함께 확인하되 실제 앱 검증은 별도 | three-inputs, validation-scopes |

같은 도식의 반복 노출은 앞뒤 장면에서 동일한 관계를 이어 설명하기 위한 선택입니다.
과장된 속도 수치를 만들지 않았고, 22→3은 원문에 있는 스토리 개수로만 사용했습니다.
MSW 패널에서 바꾸는 대상은 목 응답이며 실제 API를 수정하는 기능으로 설명하지 않았습니다.

## 완료한 검증

- `AnalysisSchema` / `validateAnalysis`: 원문 연속 인용과 근거 ID, 독립 후보 3개, 서사 순서.
- `CandidateSchema` / `validateRevision`: 필드 계약, 대본과 자막 일치, 카메라 범위.
- `validateSceneMotion`, `validatePresenterOverlay`, `validateSelection`: 모션·발표자·후보 경로.
- 공통 CTA를 공유 모듈로 추가했고, 읽기용 Markdown을 저장소 스크립트로 재생성했습니다.
- 새 도식 3장의 한글과 관계, 450×600 정적 미리보기를 육안 검토했습니다.

## 남은 확인

- 실제 영상 렌더, 전환 중간 프레임, 모바일 UI 합성, TTS 길이·음성·립싱크는 미검증입니다.
- 사진 세로 프레임·모든 헤딩 스크리블·본문/프레젠터 100px 이동은 PR #147을 적용해야 합니다.
- **블로그 교체 대기:** 자동 승인 검토가 발행된 글에서 기존 이미지 삭제를 차단했습니다.
  사용자 확인 뒤 동일 위치의 도식 3장만 교체하고 기존 발행 글을 업데이트해야 합니다.
- 기존 이미지와 새 이미지의 매핑은 `shorts/public/articles/storybook-agile/README.md`에 기록했습니다.
- `viralScore=75`는 스키마 호환을 위한 임시 편집값이며 성과 예측 또는 후보 우열을 뜻하지 않습니다.

유료 생성·TTS는 실행하지 않았습니다. 최종 렌더 승인은 별도입니다.
